## Konteks & keputusan kunci (dari diskusi)

**Pilihan user yang sudah ditetapkan:**

| Aspek | Keputusan |
|---|---|
| Auth | **Supabase Auth** — email + password only untuk MVP (OAuth Google later) |
| Email verification | **OFF untuk MVP** (instant access, bisa di-enable nanti via Supabase dashboard) |
| Quota unit | **Token-based** (tarik `usage.total_tokens` dari SSE final chunk) |
| Free tier | **1.000.000 token/bulan, renewable** tiap awal bulan kalender |
| Pro tier | **Rp 15.000/bulan, cap 50.000.000 token/bulan** (effectively unlimited untuk casual/heavy use, melindungi dari abuse) |

| Conversation history | **Tetap localStorage** (tidak sync ke DB) |
| Payment provider | **iPaymu / Qrispy** (Indonesian PG, support QRIS native) |

| Existing BYOK users | **Force re-login** — clear apiKey+baseUrl dari localStorage at first load post-deploy |
| API key / base URL | Tidak ada lagi di UI — admin (user) set di env, server-managed mode forced |
| Setup Supabase | User akan handle sendiri (buat project, run SQL, copy keys ke env) |

## Database schema (Supabase)

```sql
-- Tabel profile (link ke auth.users via FK)
CREATE TABLE profiles (
  id UUID REFERENCES auth.users ON DELETE CASCADE PRIMARY KEY,
  email TEXT NOT NULL,
  display_name TEXT,
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);

-- Subscription state per user (current active plan)
CREATE TABLE subscriptions (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES auth.users ON DELETE CASCADE,
  plan TEXT NOT NULL CHECK (plan IN ('free', 'pro')),
  status TEXT NOT NULL CHECK (status IN ('active', 'expired', 'cancelled', 'pending')),
  started_at TIMESTAMPTZ DEFAULT now(),
  expires_at TIMESTAMPTZ, -- NULL untuk free, NOT NULL untuk pro
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now(),
  UNIQUE(user_id) -- 1 user = 1 active subscription record
);

-- Token usage per user per month (rolling window)
CREATE TABLE usage_monthly (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES auth.users ON DELETE CASCADE,
  period_start DATE NOT NULL, -- first day of month
  prompt_tokens BIGINT DEFAULT 0,
  completion_tokens BIGINT DEFAULT 0,
  total_tokens BIGINT GENERATED ALWAYS AS (prompt_tokens + completion_tokens) STORED,
  message_count INTEGER DEFAULT 0,
  updated_at TIMESTAMPTZ DEFAULT now(),
  UNIQUE(user_id, period_start)
);

-- Audit log per request (untuk debugging + analytics, optional)
CREATE TABLE usage_log (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES auth.users ON DELETE CASCADE,
  model TEXT NOT NULL,
  prompt_tokens INTEGER NOT NULL,
  completion_tokens INTEGER NOT NULL,
  chat_mode TEXT,
  created_at TIMESTAMPTZ DEFAULT now()
);

-- Payment / order tracking
CREATE TABLE payments (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES auth.users ON DELETE CASCADE,
  amount INTEGER NOT NULL, -- in IDR cents (15000 = Rp 15.000)
  currency TEXT DEFAULT 'IDR',
  status TEXT NOT NULL CHECK (status IN ('pending', 'paid', 'failed', 'expired')),
  qris_payload TEXT, -- raw QRIS string from provider
  qris_image_url TEXT, -- generated QR image URL
  external_id TEXT, -- ID dari payment provider (untuk webhook reconcile)
  paid_at TIMESTAMPTZ,
  expires_at TIMESTAMPTZ NOT NULL, -- QRIS expiry, biasanya 15 menit
  created_at TIMESTAMPTZ DEFAULT now()
);

-- Indexes
CREATE INDEX idx_usage_monthly_user_period ON usage_monthly(user_id, period_start);
CREATE INDEX idx_payments_user_status ON payments(user_id, status);
CREATE INDEX idx_payments_external_id ON payments(external_id) WHERE external_id IS NOT NULL;
```

**Row Level Security (RLS):**
- `profiles`: user bisa SELECT/UPDATE row sendiri
- `subscriptions`: user bisa SELECT row sendiri (UPDATE only via service_role)
- `usage_monthly`, `usage_log`: user bisa SELECT row sendiri (INSERT/UPDATE only via service_role)
- `payments`: user bisa SELECT + INSERT row sendiri, UPDATE only via service_role

**Trigger:**
```sql
-- Auto-create profile + free subscription saat user register
CREATE OR REPLACE FUNCTION on_auth_user_created()
RETURNS trigger AS $$
BEGIN
  INSERT INTO public.profiles (id, email) VALUES (NEW.id, NEW.email);
  INSERT INTO public.subscriptions (user_id, plan, status) VALUES (NEW.id, 'free', 'active');
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created
AFTER INSERT ON auth.users
FOR EACH ROW EXECUTE FUNCTION on_auth_user_created();
```

## Token quota config

Konstanta di `app/lib/quota.ts`:
```ts
export const QUOTA = {
  free: { tokensPerMonth: 1_000_000 },        // 1 jt token/bulan
  pro:  { tokensPerMonth: 50_000_000 },       // 50 jt token/bulan (effectively unlimited untuk normal use)
} as const;

export const SUBSCRIPTION_PRICE_IDR = 15_000; // Rp 15.000
export const SUBSCRIPTION_DURATION_DAYS = 30;
```

Quota check pseudocode (di awal `/api/chat`):
```ts
const user = await getUserFromJWT(req);
if (!user) return 401;
const sub = await getActiveSubscription(user.id); // 'free' | 'pro'
const usage = await getCurrentMonthUsage(user.id);
const limit = QUOTA[sub.plan].tokensPerMonth;
if (usage.total_tokens >= limit) {
  return new Response(JSON.stringify({
    error: "Token quota exceeded",
    usage: usage.total_tokens,
    limit,
    plan: sub.plan,
  }), { status: 402 });
}
```

Token tracking di end-of-stream:
```ts
// Parse usage chunk dari SSE (9router emits di chunk terakhir):
// { "choices":[{...}], "usage": { "prompt_tokens": 100, "completion_tokens": 200, "total_tokens": 300 } }
//
// Setelah stream selesai, INSERT/UPDATE usage_monthly:
await supabaseService.rpc('increment_usage', {
  p_user_id: user.id,
  p_period: getCurrentMonthStart(),
  p_prompt: usage.prompt_tokens,
  p_completion: usage.completion_tokens,
});
// Plus INSERT usage_log untuk audit trail
```

## Risiko & mitigasi

| Risiko | Mitigasi |
|---|---|
| User register banyak akun untuk farming free quota | Email verify ON (later), atau IP rate limit di register endpoint |
| Webhook spoofing | HMAC signature verify wajib di `/api/payment/webhook` |
| Race condition di quota check | Optimistic check di awal request, atomic increment via Postgres function `increment_usage` |
| Token tracking gagal di edge runtime | Pakai `waitUntil()` (Next.js Edge) untuk fire-and-forget |
| Supabase tier free habis | Monitor; upgrade ke Pro Supabase ($25/bln) kalau >500 user |
| QRIS expired sebelum user bayar | Default expires 15 menit, user bisa "regenerate" yang akan create payment row baru |
| RLS bypass | Service role key strictly env-only, audit code untuk pastikan `NEXT_PUBLIC_` tidak dipasang |
